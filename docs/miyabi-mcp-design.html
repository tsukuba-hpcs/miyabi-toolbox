miyabi-toolbox · miyabi-mcp · 设计说明

服务跑在 PBS 旁边，
agent 在哪里都用同一组工具

miyabi-mcp 把 Miyabi 的 PBS 做成 16 个带护栏的 MCP 工具。写操作先出计划再提交，长等待变成通知，每个作业都记进项目自己的台账。

v0.1 · main 分支 b54210f · 2026-11-06 · Python ≥ 3.11，核心只用标准库 · 站点数字带日期，会过时

接入

远端 agent 只注册 pi-env-mcp，服务端搭它已有的连接

服务端必须在登录节点上：PBS 命令、作业日志和台账都在那里。放在工作站上，每次读文件和执行命令都要跨 ssh，等于重做一遍 pi-env-mcp。miyabi-mcp 的代码不依赖 pi-env-mcp：pi-env-mcp 管连接、文件、终端和传输，miyabi-mcp 管 PBS 语义。

注册命令（方式 B） 
# 工作站：pi-env-mcp 里已经 add 并 trust 过主机 miyabi-g
pi-env-mcp mcp add miyabi-pbs --host miyabi-g -- \
  <path>/miyabi-mcp/bin/miyabi-mcp serve --project <project> \
  --notifier <工作站名> --local-launcher <本机 bin/miyabi-mcp> --remote-alias miyabi-g

# agent 只注册 pi-env-mcp；工具名是 mcp__miyabi-g__miyabi_pbs__<工具>
claude mcp add --scope user miyabi-g -- pi-env-mcp serve --host miyabi-g
  • 在 pi-env-mcp 的配置里给这一项加 "timeout": 300，mcp add 没有对应的参数。
  • 不要给这一项设 --description：pi-env-mcp 会用它整个替换服务端的 instructions。
  • --project 要写明：托管时服务端的工作目录是主机配置的 cwd 或远端 home，推断不出项目。
  • --remote-alias 同时是 pi-env-mcp 里的主机名和 ~/.ssh/config 里的别名，所以两者要同名。

工具

一半工具只读；只有 job_cancel 是破坏性的

所有工具都接受可选的 project 参数。每个工具都有对应的 CLI 子命令，输入相同，输出同一份 JSON，所以只有 shell 的 agent 也能用。

结构

CLI 与 MCP 共用一套实现；只有 server.py 依赖 MCP SDK

提交

提交分两步：先出计划，再凭摘要提交

写操作出错时一律拒绝（fail closed）：先计划后提交，有策略上限和幂等键，结果不确定时先对账，再决定是否重试。

台账

PBS 是事实来源，台账是缓存和意图日志

每个作业一份 JSON 记录，另有按月追加的事件日志。不用 SQLite：几台登录节点上可能同时有多个写者。记录用原子 rename 替换；锁是 Lustre 上的 flock，在登录节点之间一致，持锁进程退出时自动释放。

上限

每次提交都在一把锁里过三层上限

多个项目同时跑是常态。PBS 的项目上限和 token 预算按组计，由组内所有项目、所有用户共享，所以上限分组、用户、项目三层。上限只用于检查，永远不作为申请的 walltime。

通知

判定在登录节点，投递在 agent 所在的机器

agent 等作业时可能正在做别的事，也可能已经结束回合，所以这里叫“通知”，不叫“唤醒”。agent 每次登记或加入通知后，都运行返回的命令；notifyd ensure 是幂等的，不以“已在运行”为由跳过。

托管

托管有四条约束，都在 miyabi-g1 上实测过

  • 会话满时，错误看起来像认证失败。会话被拒后 ssh 改为直连，在 BatchMode 下登录不了，错误结尾是 Permission denied (publickey)。notifyd 隔 2 s、5 s 各重试一次，仍被拒就报 ssh_sessions_full，请用户关掉不用的 MCP 客户端。
  • 超时的提交可能已经提交了。pi-env-mcp 超时后发 notifications/cancelled：job_wait 随即结束，其他工具在后台线程里照常做完。用同一个 request_key 重试会拿回那个作业；没带键时先用 job_list 确认。
  • agent 看不到 serverInfo.version。pbs_context.server.commit 写出运行中的提交；checkout 前进后，每个结果都带 server_note，请 agent 重启 MCP 服务。
